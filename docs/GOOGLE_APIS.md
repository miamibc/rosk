# Google APIs: возможности и ограничения

Этот документ фиксирует, что реально можно сделать через API Google, потому что именно это
определяет границы фич Rosk. Пункты с пометкой «проверить» нужно подтвердить прототипом.

## 1. Авторизация через GNOME Online Accounts (GOA)

Проверено на целевой машине (Ubuntu 26.04, GNOME Shell 50.1, libgoa-backend-1.0.so.2):
провайдер `google` запрашивает scopes:

```
userinfo.email, userinfo.profile, calendar, m8/feeds, carddav, mail.google.com,
https://www.googleapis.com/auth/tasks
```

Выводы:

- **Google Tasks** — доступен через токен GOA (`Goa.OAuth2Based.call_get_access_token`).
  Своё OAuth-приложение и client_id для Tasks не нужны.
- **Google Keep** — scope `keep` в GOA **отсутствует**. Через GOA доступ к Keep получить нельзя.
- Флаг `CalendarDisabled` в GOA, по всей видимости, управляет и задачами (у EDS backend `gtasks`
  это так) — проверить; если пользователь отключил «Календарь» в настройках аккаунта, Rosk должен
  показать понятное сообщение.

## 2. Google Tasks API v1

Ресурсы: `tasklists` (списки) и `tasks` (задачи).

### Поля задачи

| Поле | Запись | Примечание |
|---|---|---|
| `id`, `etag`, `selfLink` | нет | |
| `title` | да | до 1024 символов |
| `notes` | да | до 8192 символов, plain text |
| `status` | да | `needsAction` / `completed` |
| `due` | да | RFC 3339, **но хранится только дата — время API отбрасывает** |
| `completed` | да | дата-время выполнения |
| `parent` | через `tasks.move` | подзадачи; Google показывает **один уровень** вложенности |
| `position` | через `tasks.move` | порядок внутри родителя |
| `deleted`, `hidden` | да / нет | `hidden` — выполненные и «очищенные» задачи |
| `updated` | нет | время последнего изменения на сервере |
| `links[]` | нет | ссылки на источник (например, письмо Gmail) |
| `webViewLink` | нет | ссылка на задачу в веб-интерфейсе |
| `assignmentInfo` | нет | задача назначена из Docs / Chat / Spaces |

Проверено 2026-11-20 на реальном аккаунте: задача со сроком «Thu 26 Nov, 13:05» в мобильном
Google Tasks приходит из API как `"due": "2026-11-26T00:00:00.000Z"` — время теряется. Ссылка на
письмо приходит в `links[]` (`type: email`). Звёздочки в ответе нет.

### Чего в API нет (есть только в UI Google)

- **время срока** (`due` только дата; время отбрасывается). Endeavour тоже показывает только
  дату — см. ADR-006;
- **повторяющиеся задачи** — API не отдаёт правило повторения;
- **«звёздочка» / избранное**;
- **напоминания** (уведомления Google о задаче со временем).

Следствие: Rosk поддерживает всё, что есть в API, а время, повторение и напоминания реализует
сам, только локально (ADR-006).

### Методы, важные для синхронизации

- `tasks.list` с `updatedMin`, `showDeleted=true`, `showHidden=true`, `showCompleted=true`,
  пагинация `pageToken`, `maxResults<=100` — инкрементальная загрузка изменений.
- `tasks.insert` (с `parent`, `previous`), `tasks.patch`, `tasks.delete`, `tasks.move`
  (`parent`, `previous`, `destinationTasklist` — перенос между списками, проверить доступность).
- `tasks.clear` — скрыть все выполненные задачи списка.
- `tasklists.list/insert/patch/delete`.
- Квота по умолчанию: 50 000 запросов/день на проект — для одного пользователя с запасом.
  Поскольку используется client_id GNOME (через GOA), квота общая с другими приложениями GOA —
  делать запросы экономно (инкрементально, без частого полного опроса).

## 3. Google Keep API

### Официальный API (`keep.googleapis.com/v1`)

- Доступен **только для аккаунтов Google Workspace** (корпоративных/учебных), требует настройки
  администратором. Для обычных `@gmail.com` аккаунтов недоступен.
- Методы: `notes.create`, `notes.get`, `notes.list`, `notes.delete`, `permissions.*`,
  `media.download`. **Метода update нет** — заметку нельзя изменить, только удалить и создать заново
  (с потерей id, даты создания и т.д.).
- Поля: `title`, `body` (текст ИЛИ список с `listItems[]`: `text`, `checked`, `childListItems`),
  `attachments` (только чтение), `permissions`, `trashed`. Цвета, меток, закрепления, архива,
  напоминаний в официальном API нет.

### Неофициальный путь (`gkeepapi`, Python)

- Использует внутренний протокол Keep и «master token», полученный через Android-логин (`gpsoauth`).
- Умеет почти всё: чтение/изменение заметок и списков, цвета, метки, закрепление, архив.
- Риски: может сломаться при изменении протокола; Google может потребовать подтверждение входа
  или заблокировать токен; master token даёт широкий доступ к аккаунту — хранить только в
  libsecret. Использование неофициального протокола формально не одобрено Google.

### Вывод

Синхронизация с Keep — **опциональный адаптер** с явным предупреждением. Без него заметки
Rosk работают локально и полноценно. Задачи (основная ценность) синхронизируются надёжно через
официальный Tasks API.
