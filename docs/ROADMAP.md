# Roadmap

Каждый этап заканчивается работающим приложением, которым можно пользоваться.

Статус на 2026-11-20 (версия 0.1): M0–M6 сделаны. Не проверено вживую: расширение GNOME Shell
(загрузится после перезахода в сеанс) и вход в Keep (нужен cookie пользователя). M7 и M8 — на будущее.

## M0. Прототипы рисков (1–2 дня)

- Получить токен из GOA и выполнить `tasklists.list` / `tasks.list` / `tasks.insert`.
- Проверить: `tasks.move` с `destinationTasklist`; связь
  `CalendarDisabled` с доступом к задачам.
- Проверить `gkeepapi` на реальном аккаунте: вход, чтение, изменение заметки, метки.

## M1. Ядро и оффлайн

- `core/`: модель, правила сроков и подсветки, разбор быстрого ввода (ru/en) + тесты.
- `store/`: схема SQLite, миграции, очередь операций, FTS.
- Минимальное главное окно: списки, задачи, подзадачи, выполнение, редактирование.

## M2. Синхронизация с Google Tasks

- Адаптер Tasks, push/pull, merge, индикатор статуса, обработка ошибок и отсутствия сети.

## M3. Быстрый ввод

- Фоновая служба + D-Bus API + автозапуск.
- Расширение GNOME Shell: индикатор, счётчик, popup, горячая клавиша.
- Search provider.

## M4. Сроки и уведомления

- Умные представления «Сегодня» / «Предстоящие», подсветка сроков, утренняя сводка.

## M5. Заметки

- Локальные заметки: текст, чек-листы, метки, цвета, закрепление, архив.
- Адаптер Keep через `gkeepapi` (ADR-004).
- Преобразование задача <-> заметка.

## M6. Полировка и выпуск

- Анимации, клавиатурная навигация, адаптивность, переводы, иконка.
- `make install` / `make uninstall`, релизный `tar.gz` через GitHub Actions (ADR-010).

## M7. Внутренний API Google Tasks (на будущее)

Цель: время срока, напоминания, повторение и звёздочка — то, что есть в мобильном Google Tasks,
но отсутствует в публичном API.

- Посмотреть сетевые запросы tasks.google.com в браузере: endpoint, формат, поля времени,
  повторения, звезды.
- При необходимости разобрать APK Google Tasks (apkmirror), чтобы понять, как получить токен
  вне браузера — вероятно, тем же способом, что и для Keep (`gpsoauth`, master token).
- Адаптер `sync/tasks_internal.py` поверх публичного: публичный API остаётся основным, внутренний
  только дополняет поля. Если внутренний сломается — Rosk продолжает работать с датами.

## M8. Картинки в Keep: добавление и удаление (на будущее)

Сейчас картинки и рисунки из Keep только показываются (скачиваются при синхронизации в `media/`).

Цель: прикреплять картинки к заметкам из Rosk и удалять их.

- Загрузка. В gkeepapi `__UNSTABLE_API_uploadMedia` — пустая заглушка: как Android-приложение
  Keep загружает файл, никто не разбирал. Посмотреть трафик приложения (эмулятор + mitmproxy)
  или разобрать APK Google Keep: на какой сервер уходит файл, как получить `serverId` картинки и
  как привязать её к заметке (узел `BLOB` с `parentId` заметки). Проверить, подходит ли для
  этого тот же master token, что и для синхронизации.
- Удаление. Картинка в gkeepapi — обычный дочерний узел заметки, его можно пометить удалённым
  (`blob.delete()`) и отправить при синхронизации, как пункты списков. Проверить вживую на
  временной заметке, что Keep действительно убирает картинку, а не восстанавливает её.
- Если загрузка окажется возможной: вставка из буфера обмена и перетаскивание файла в редактор,
  отправка через outbox, как остальные изменения; пока заметка не синхронизирована, показывать
  локальный файл.
