# Архитектурные решения (ADR)

Статусы: **Предложено** — ждёт подтверждения; **Принято**; **Отклонено**.

## ADR-001. Язык и UI-стек — Принято: Python

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Python 3 + PyGObject + GTK4 + libadwaita** | самая быстрая разработка; GOA, libsecret, Soup, уведомления — через GObject Introspection (всё уже установлено в системе); единственная зрелая библиотека для Keep (`gkeepapi`) — на Python | старт процесса ~300–500 мс (решается фоновой службой); слабее типизация (решается mypy) |
| Rust + gtk4-rs + libadwaita | скорость, один бинарник, строгие типы | разработка в 2–3 раза дольше; нет библиотеки Keep |
| Vala + GTK4 | «родной» язык GNOME | маленькая экосистема, Keep — с нуля |
| Electron / Tauri | привычный веб-стек | не выглядит как GNOME-приложение, тяжёлый |

Приложение и служба — Python 3.14 + GTK4 + libadwaita 1.9. Расширение GNOME Shell —
JavaScript (GJS), других вариантов Shell не допускает.

## ADR-002. Авторизация через GOA для Tasks — Принято

GOA уже выдаёт scope `tasks` (проверено, см. GOOGLE_APIS.md §1). Своё OAuth-приложение не нужно.

## ADR-003. Offline-first с локальной SQLite и очередью операций — Принято

Локальная база — источник истины для UI. Синхронизация — фоновая, 3-way merge на уровне полей.

## ADR-004. Keep через `gkeepapi` — Принято

Аккаунт — обычный Gmail, поэтому официальный Keep API недоступен (он только для Workspace).
Единственный способ синхронизировать заметки с Keep — неофициальная `gkeepapi`. Решение:

- синхронизация заметок с Keep — через `gkeepapi`, адаптер изолирован в `sync/keep.py`;
- при подключении пользователь один раз проходит вход Google (получение master token), токен
  хранится только в libsecret;
- если Keep-синхронизация сломается (Google изменил протокол, токен отозван) — заметки продолжают
  работать локально, изменения копятся в очереди, в UI показывается понятная ошибка;
- задачи от Keep никак не зависят.

## ADR-005. Одно приложение, единая модель, раздельные бэкенды — Принято

Задачи и заметки — один UI и одна таблица `item` с полем `kind`, но каждый `kind` синхронизируется
только своим адаптером. Перевод между типами — явная операция (создать в целевом + удалить в исходном).

## ADR-006. Срок — только дата — Принято

Срок (deadline) синхронизируется с Google через поле `due`: его видно в веб-интерфейсе Google
Tasks, в мобильном приложении и в Endeavour.

Время суток, напоминания, повторение и звёздочка в приложениях Google есть, но публичный
Tasks API их не отдаёт (проверено, GOOGLE_APIS.md §2): задача «Thu 26 Nov, 13:05» приходит как
`2026-11-26T00:00:00.000Z`. Endeavour тоже показывает только дату (`gtd-task-row.c`,
`gtd-edit-pane.c`).

Решение: в первой версии срок — только дата. Локально время не храним и маркеров в `notes` не
пишем. Время, напоминания, повторение и звёздочку добавим после исследования внутреннего API
Google Tasks (ROADMAP M7). Схема БД оставляет под них место.

## ADR-007. Быстрый ввод — расширение GNOME Shell — Принято

В GNOME нет трея по умолчанию; индикатор в панели и popup реализуются расширением, которое
открывается мгновенно (уже загружено в процесс Shell). Дополнительно: глобальная клавиша и
search provider.

## ADR-008. Application ID — Принято

`io.github.miamibc.rosk` — ID приложения, имя на шине D-Bus и префикс GSettings-схем.
UUID расширения: `rosk@miamibc.github.io`.

## ADR-009. Подзадачи — один уровень — Принято

Как в Google Tasks.

## ADR-010. Упаковка — без Flatpak, как в picco — Принято

В picco: `make release` собирает один бинарник, `make install` кладёт его в `~/.cargo/bin`,
а `.desktop` и иконки — в `~/.local/share`; GitHub Actions выкладывает `tar.gz` в релизы.

Для Python то же самое:

- **Зависимости системы** (из Ubuntu, уже стоят): `python3`, `python3-gi`, `gir1.2-gtk-4.0`,
  `gir1.2-adw-1`, `gir1.2-goa-1.0`, `gir1.2-secret-1`, `gir1.2-soup-3.0`.
- **Pip-зависимости** (`gkeepapi` и её зависимости) — в собственный venv
  `~/.local/lib/rosk/venv` с `--system-site-packages`, чтобы видеть системный `gi`.
- **`make install`** (в домашний каталог, без root): код -> `~/.local/lib/rosk` (данные пользователя — отдельно, в `~/.local/share/rosk`), запуск ->
  `~/.local/bin/rosk`, `.desktop`, иконки, GSettings-схема, D-Bus service file, автозапуск
  службы (`~/.config/autostart`), расширение -> `~/.local/share/gnome-shell/extensions/`.
- **`make uninstall`** — убирает всё это, данные пользователя не трогает.
- **Релиз** — `rosk-<version>.tar.gz` с исходниками и Makefile (GitHub Actions, как в picco).

Flatpak пока не нужен: песочница усложняет доступ к GOA и расширению, а выигрыша для личного
использования нет. Можно добавить позже.
